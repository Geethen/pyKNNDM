CAST::knndm · spatial cross-validation

How knndm builds folds

k-fold Nearest Neighbour Distance Matching chooses cross-validation folds so that the distances a model is tested at look like the distances it will predict at. This page walks through every step on a real run of the algorithm.

The problem with random folds

Field samples are rarely spread evenly. They come in clusters: along roads, around stations, inside study sites. A map, though, is predicted everywhere. With random k-fold cross-validation, almost every test sample still has a close neighbour from the same cluster in the training set, so the model is tested on easy interpolation. The error estimate comes out too optimistic for the places the map actually covers.

knndm fixes the folds rather than the model. It holds out whole groups of nearby samples, choosing how coarse those groups are so that test samples end up as far from their training data as prediction locations are from theirs.

Three nearest-neighbour distances

Everything in knndm is measured with one quantity: the distance from a point to its nearest training sample. It is computed for three sets of points, and the method compares their empirical cumulative distributions (ECDFs).

Gij prediction → sample

For each prediction location, the distance to the nearest training sample. This is the situation the model faces when it makes the map.

Gj sample → sample

For each training sample, the distance to its nearest other sample. This is what leave-one-out or random CV tests.

Gj* CV distance

For each training sample, the distance to the nearest sample in a different fold. This is what a given fold design tests. knndm tunes the folds to make it match Gij.

The quality of a fold design is the area between the Gj* and Gij ECDFs, the 1-Wasserstein distance W, measured in map units (metres here). Smaller is better. knndm searches for the fold design with the smallest W.

The algorithm, step by step

These are the steps CAST runs, in order, with the defaults k = 10, maxp = 0.5, clustering = "hierarchical", linkf = "ward.D2" and nk_len = 100. The example on this page uses k = 5.

  1. Measure. Compute Gij and Gj with exact nearest-neighbour search.

  2. Decide whether clustering is needed. Run a one-sided Kolmogorov–Smirnov test that prediction distances are larger than sample distances. If p ≥ 0.05, the samples already cover the area like a random design, and knndm returns ordinary random k-fold CV.

  3. Cluster once. Build a hierarchical clustering tree of the sample coordinates (or, with kmeans, run k-means separately for every candidate number of clusters).

  4. Try many granularities. For each nk on a log-spaced grid from k to n − 2, cut the tree into nk clusters and merge them into k folds (see “From clusters to folds” below).

  5. Score. Skip the design if any fold holds more than maxp of the samples. Otherwise compute Gj* for these folds and its W against Gij.

  6. Keep the best. Return the folds with the smallest W, and report that nk as q. The folds come back as train/test index lists ready for caret::trainControl.

Why does a single number of clusters control everything? With few large clusters, whole regions are held out, so test samples are far from training data and Gj* overshoots. With many tiny clusters, each fold is a scatter of small groups, which is almost random CV, so Gj* undershoots. Somewhere in between, the distances match.

From clusters to folds

Step 4 has to turn nk clusters into exactly k folds. CAST does this with a simple, deterministic rule:

  1. Project each cluster’s centroid onto the first principal component of the sample coordinates and sort the clusters along it.

  2. Walking in that order, every cluster with at least n/k samples gets a fold of its own.

  3. The remaining clusters are dealt out to the remaining folds in turn, like cards (1, 2, … k, 1, 2, …), in the same order.

What knndm returns

The result holds the fold label for each sample (clusters), the train and test index lists for each fold (indx_train, indx_test), the three distance vectors Gij, Gj and Gjstar, and W and q. With test_prop, it returns a single train/test split instead, using the same search with k = 2 and a tolerance on the test share.

Limitations

knndm is a pragmatic heuristic. Knowing where it is weak helps you read its output.

Method

Only one distance statistic is matched

The target is the distribution of nearest-neighbour distances, nothing else. Two fold designs with the same ECDF can test very different parts of the map. Matching geography does not make folds representative in predictor (feature) space, and knndm runs geographic and feature space separately, never jointly.

Method

CV cannot test beyond the data

If prediction locations lie further from the samples than any held-out group can be, Gj* cannot reach Gij and the minimum W stays large. knndm still returns folds, but a large residual W is a sign that the map extrapolates.

Method

The result depends on the prediction sample

Gij comes from predpoints or from points sampled in modeldomain. Too few points, or a sample that over-represents some part of the area, shifts the target and therefore the chosen folds.

Method

The cluster-to-fold rule is one-dimensional

Folds are assembled by sorting clusters along a single principal axis and dealing them out in turn. Clusters that are neighbours on the map but far apart on that axis can land in different folds, and folds are often stitched from distant pieces, as in the example above. The rule is fast, but nothing optimises it.

Method

A narrow search

Only one tree (or one k-means start per nk, with nstart = 1) and one linkage are tried, on a fixed grid of nk. The best design found is the best of about 100 candidates, not the best possible.

Method

Fold sizes are only bounded above

maxp stops one fold from dominating, but there is no lower bound. Very small folds give noisy per-fold errors.

Method

An all-or-nothing gate

The KS test at 0.05 decides between random CV and the search. With many prediction points, trivial differences become significant. With few samples, the test can miss real clustering. Either way, the method never compares the two options by their W.

Method

W weights all distances equally

It is in map units, so it is hard to compare between datasets, and it treats a mismatch at short distances like one in the upper tail, where extrapolation errors concentrate.

Implementation

Quadratic memory and hidden randomness

Hierarchical clustering needs the full n × n distance matrix (R caps it at 65,536 points; 10,000 points already need about 400 MB). k-means and the random fallback depend on the seed, and CreateSpacetimeFolds reseeds R’s global RNG from sample(1:1000, 1), so later random draws in your script change too.

Implementation

Quirks in CAST 1.1.2

knndm_geo evaluates W twice per nk, and the second check only tests maxp. With test_prop, a split outside the lower tolerance can therefore still be chosen. The Python port reproduces this on purpose, to stay bit-exact.

This port

Scope of the Python version

Not ported: modeldomain sampling, and the mahalanobis, gower (categorical) and great-circle distances. With more than 25 predictors, the PCA ordering uses SciPy’s LAPACK and may differ from R in near-tie cases.

Ways knndm could improve

Most of these keep the core idea of matching Gj* to Gij and change how the folds are searched for or judged. The neighbour index in the Rust backend makes re-scoring a fold design cheap, which makes the search-based ideas practical.

Optimise the cluster-to-fold assignment

Start from CAST’s PC1 assignment, then move or swap clusters between folds while W decreases (local search or simulated annealing), with a penalty for unequal fold sizes. Only the samples whose nearest other-fold neighbour changes need re-scoring.

Search wider, then refine

Score several linkages and several k-means starts, and refine nk between the neighbours of the best grid value. Report the best design, and how much better it is than the default.

Replace the KS gate with a comparison

Always compute W for random CV as well, and return whichever design has the lower W. This removes the arbitrary 0.05 threshold.

Constrain fold sizes in both directions

Add a minimum fold share for k-fold CV, or penalise fold-size variance in the objective, so per-fold errors stay stable.

Match a richer target

Weight the upper tail of the distance distribution, match k-th nearest-neighbour distances as well as the first, or combine geographic and feature-space distances in one objective.

Weight the prediction domain

Weight prediction points by the area or importance they represent, and sample them in strata, so that Gij describes the map users actually care about.

Report diagnostics and uncertainty

Return the W-versus-nk curve, the fold sizes and the merge table (as this page does), and bootstrap over prediction samples to show how stable the choice is. When the minimum W is large relative to typical Gij, point users to an area-of-applicability analysis (CAST::aoa).

Scale beyond the distance matrix

Ward clustering can run on coordinates with a nearest-neighbour chain in linear memory, and mini-batch k-means handles very large samples. These would suit an explicitly non-bit-exact “fast” mode in the Python port.
